# Document Understanding Self-Supervised Tasks

This document defines the specifications for self-supervised tasks based on the OmniDocParser outputs.

## 1. Basic Reading Capabilities (Img -> Text)
- **Objective**: Extract all text from a document image in the correct reading order.
- **Input**: Image of a full page.
- **Output**: Plain text string.
- **OmniDocParser Ground Truth Generation**: Iterate over all text-bearing elements (`<text-block>`, `<title>`, `<table>` body text, `<math-block>`, etc.) in the XML following their sequential order. Concatenate their text content into a single continuous string.

## 2. OCR (Img -> Text + BBox)
- **Objective**: Extract text and its spatial location.
- **Input**: Image of a full page.
- **Output**: Sequence of text blocks and their bounding boxes (e.g., `[x1, y1, x2, y2] Text content...`).
- **OmniDocParser Ground Truth Generation**: Extract the `bbox` attribute and inner text for every text-bearing XML element. 
- **Note for Future Implementation**: *Currently implemented at the **block level** due to OmniDocParser's native output constraints. Future iterations should explore injecting a secondary word-level OCR engine to provide true word-level bounding boxes.*

## 3. Layout of the page
- **Objective**: Identify layout elements and their spatial locations.
- **Input**: Image of a full page.
- **Output**: A sequence of layout class labels and their bounding boxes (e.g., `[62, 130, 940, 400] <figure>`, `[62, 80, 940, 120] <text-block>`).
- **OmniDocParser Ground Truth Generation**: Iterate over all XML elements that possess a `bbox` attribute. Extract the bounding box coordinates and the XML tag name as the layout class.

## 4. Img -> Markdown
- **Objective**: Generate a semantic markdown representation of the page.
- **Input**: Image of a full page.
- **Output**: Markdown string.
- **OmniDocParser Ground Truth Generation**: Construct an `xml_to_markdown` converter. Map `<title level="N">` to `N` hash symbols. Map text blocks to raw text. For figures, generate `![caption](image_path)`. For tables, inject the raw HTML provided by the `<table-body>` tag directly into the Markdown string.

## 5. Page Img -> Tree of the page
- **Objective**: Generate the structured DOM/XML logical hierarchy of the page.
- **Input**: Image of a full page.
- **Output**: The XML string representing the page structure (without bounding boxes).
- **OmniDocParser Ground Truth Generation**: Extract the `<page>` XML block from the output and run a sanitization pass to strip out all `bbox` attributes, leaving only the tags and text content.

## 6. DOM Tree Edition (Error Correction)
- **Objective**: Correct a faulty XML logical tree using the page image as the visual ground truth.
- **Input**: Image of a full page AND a corrupted XML string (without bounding boxes).
- **Output**: The corrected XML string (without bounding boxes).
- **OmniDocParser Ground Truth Generation**: The target is the sanitized (bbox-free) XML from Task 5. The input is generated by taking this valid XML and programmatically injecting structural mutations (e.g., deleting nodes, changing tag types, or shuffling element order).

## 7. Contrastive Image Selection (Positive/Negative)
- **Objective**: Cross-modal retrieval and fine-grained semantic alignment.
- **Input**: A text snippet (e.g., a text block or caption) AND a set of $N$ cropped image candidates (1 positive, $N-1$ negatives).
- **Output**: The index (0 to $N-1$) of the correct matching image.
- **OmniDocParser Ground Truth Generation**: Select an element (like a `<figure>`) from the XML. The "Positive" image is generated by cropping the raw page image using the element's `bbox`. The "Negative" images are generated by cropping other random elements across the document using their respective bounding boxes.

## 8. Page Sorting
- **Objective**: Understand multi-page narrative flow and document structure.
- **Input**: A shuffled sequence of $N$ full-page images from a single document.
- **Output**: A list of indices representing the correct original reading order.
- **OmniDocParser Ground Truth Generation**: Extract $N$ sequential pages based on `page idx`. Programmatically draw black boxes over the coordinates of any `<page-number>` XML elements on the raw images to prevent the model from trivializing the task. The target is the unshuffled sequence index.

## 9. Document Reconstruction (Text/Images -> Layout)
- **Objective**: Spatial reasoning and layout understanding. Reassemble a page given its isolated elements.
- **Input**: A list of cropped element images (or their text contents) presented in a randomized order.
- **Output**: The target bounding box `[x1, y1, x2, y2]` for each element, defining where it should be placed on the canvas.
- **OmniDocParser Ground Truth Generation**: Use OmniDocParser's `bbox` attributes to crop the elements from the page image. The input is the shuffled set of crops; the target is the original array of bounding boxes.

## 10. Ordering Figures
- **Objective**: Ground isolated visual references to their correct context.
- **Input**: A set of full-page images from a document AND a set of cropped figure images from that document.
- **Output**: A mapping that assigns each figure to the correct page index where it appears.
- **OmniDocParser Ground Truth Generation**: Iterate through the parsed pages, extract `<figure>` tags, crop them using their `bbox`, and map them to their origin `page idx`.

## 11. Form Filling
- **Objective**: Key-Value Information Extraction (KVIE) from structured forms.
- **Input**: Image of a form page.
- **Output**: Structured JSON of key-value pairs representing the filled data.
- **Ground Truth Generation Note**: *OmniDocParser does not natively extract Key-Value pairs. For this specific task, the pipeline will bypass OmniDocParser GT generation and instead pull ground truth annotations directly from the pre-processed **CommonForms** dataset partition.*
